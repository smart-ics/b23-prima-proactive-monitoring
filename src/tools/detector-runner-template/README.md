# PrIMA Reference Detector Runner & SDK Guide

This guide documents the architecture, configuration, deployment, and authoring of custom detector probes using the **PrIMA Reference Detector SDK** (`PrIMA.Detectors`).

---

## 1. Overview & Architecture

The PrIMA Reference Detector Runner is a lightweight, edge-deployed worker process designed to run on hospital servers alongside or near hospital SIMRS databases. It executes automated inspection probes against hospital operational databases without placing locks or causing OLTP contention.

### Core Capabilities

- **Zero-Touch Bootstrap Handshake (`DEC-001`, `DEC-002`, `DEC-005`):** Automatically registers or synchronizes detector manifests with the PrIMA central server using short-lived 24-hour enrollment tokens (`PRM-TOKEN-...`), obtaining and locally caching per-detector API keys (`prm_key_...`) in `.prima-credentials.json`.
- **Dual Execution Modes:**
  - **Continuous Daemon Mode (Default):** Runs as an autonomous background service executing periodic cadence timers (`PeriodicTimer`) for each probe.
  - **CLI Run-Once Mode (`--run-once`):** Executes exactly one inspection pass, submits telemetry, and exits with code `0` (clean) or `1` (failure) for integration with Windows Task Scheduler or cron.
- **Embedded Kestrel Webhook Listener:** Listens on a configurable HTTP port (default `5090`) mapping `POST /webhooks/{detectorKey}` to execute on-demand synchronous inspection runs within a 15-second contract for instant UI verification (`S-02` / `S-04`).
- **Automatic Failsafe Exception Trapping (`BR-PRIMA-005`):** Probes cannot crash the runner; unhandled exceptions, SQL timeouts, and network errors are trapped into `ExecutionFailed` telemetry reports with full stack traces and error messages.
- **Non-Intrusive SIMRS Safety Guardrails (`BR-PRIMA-007`, `DEC-008`):** All SQL queries enforce `ApplicationIntent=ReadOnly`, `SET TRANSACTION ISOLATION LEVEL READ UNCOMMITTED; SET LOCK_TIMEOUT 2000;`, 5-second command timeouts, and static DML mutation keyword rejection.

```
+-----------------------------------------------------------------------------------+
|                        Hospital Edge Runner (PrIMA.Detectors)                     |
|                                                                                   |
|  [ Bootstrap Handshake Service ] <----> Central PrIMA API (/api/detectors/...)   |
|         | Caches Credentials                                                      |
|         v                                                                         |
|  [.prima-credentials.json]                                                        |
|         |                                                                         |
|  +--------------------+---------------------+----------------------------------+  |
|  | Daemon Mode        | CLI Mode            | Webhook Listener                 |  |
|  | (PeriodicTimer)    | (--run-once)        | (POST /webhooks/{detectorKey})   |  |
|  +--------------------+---------------------+----------------------------------+  |
|                                                                                   |

|         |                                                                         |
|         v                                                                         |
|  [ ReadOnlySimrsConnectionFactory ] ---> Hospital SIMRS Database (READ UNCOMMITTED)|
+-----------------------------------------------------------------------------------+
```

## 2. Prerequisites

- **Runtime:** .NET 8 SDK or .NET 8 ASP.NET Core Runtime.
- **Network Access:**
  - Outbound HTTPS/HTTP to Central PrIMA Server (`http://<prima-server-ip>:5000` or `https://<prima-domain>`).
  - Outbound TCP to Hospital SIMRS SQL Server (Port 1433).
  - Inbound HTTP on Port 5090 (or configured port) from Central PrIMA Server (if on-demand webhook execution is required).

## 3. Configuration

### Environment Variables

| Variable | Description | Example |
|---|---|---|
| `PRIMA_ENROLLMENT_TOKEN` | 24-hour single-use token generated by EDP officer from UI | `PRM-TOKEN-a8f2...` |
| `PRIMA_SERVER_URL` | Base URL of the central PrIMA API server | `http://192.168.1.100:5000` |
| `PRIMA_WEBHOOK_PORT` | Port for embedded Kestrel webhook listener | `5090` |
| `PRIMA_WEBHOOK_BASE_URL` | Externally reachable URL of this runner for webhooks | `http://192.168.1.50:5090` |
| `ConnectionStrings__ReadOnlySimrsDb` | Read-only connection string to hospital SIMRS database | `Server=simrs-db;Database=SIMRS;...` |

## 4. Quick Start: Enrollment & Running

### Step 1: Generate Enrollment Token
In the PrIMA web UI, navigate to **Detectors (S-03)** and click **"Quick Enroll (Handshake)"**. Copy the generated token.

### Step 2: Configure Environment
```bash
# Windows PowerShell
$env:PRIMA_ENROLLMENT_TOKEN = "PRM-TOKEN-..."
$env:PRIMA_SERVER_URL = "http://localhost:5000"

# Linux / Bash
export PRIMA_ENROLLMENT_TOKEN="PRM-TOKEN-..."
export PRIMA_SERVER_URL="http://localhost:5000"
```

### Step 3: Run in Daemon Mode
```bash
dotnet run --project src/backend/PrIMA.Detectors/PrIMA.Detectors.csproj
```
On boot, the runner will:
1. Detect `PRIMA_ENROLLMENT_TOKEN`.
2. Post probe manifests to `POST /api/detectors/handshake`.
3. Receive unique `detectorId` and `apiKey`.
4. Cache credentials into `.prima-credentials.json`.
5. Start periodic inspection loops on background timers.
6. Open Kestrel webhook endpoint at `http://0.0.0.0:5090`.

### Step 4: Run in CLI Mode (Windows Task Scheduler / Cron)
```bash
dotnet run --project src/backend/PrIMA.Detectors/PrIMA.Detectors.csproj -- --run-once
```
The runner executes a single inspection pass, pushes telemetry, and exits with code `0` (or `1` on failure).

## 5. Authoring a Custom Detector Probe

To author a new custom detector probe:

### Step 1: Implement `IDetectorProbe`

Create a new probe class implementing `IDetectorProbe`:

```csharp
using PrIMA.Detectors.Sdk;

namespace PrIMA.Detectors.Probes;

public sealed class PharmacyExpiryDetectorProbe : IDetectorProbe
{
    public DetectorManifest Manifest { get; } = new(
        name: "Pharmacy Expiry Discrepancy Detector",
        targetModule: "Pharmacy",
        scope: "DataIntegrity",
        expectedCadenceSeconds: 300,
        description: "Detects unexpired dispensed batches referencing obsolete drug master batches.",
        version: "1.0.0",
        webhookEndpointKey: "pharmacy-expiry-detector"
    );

    public async Task<TelemetryReport> ExecuteInspectionAsync(CancellationToken ct = default)
    {
        // Execute inspection logic...
        var findings = new List<FindingItem>();

        // If no anomalies found:
        if (findings.Count == 0)
        {
            return TelemetryReport.Passed(executionDurationMs: 45);
        }

        // If anomalies discovered:
        return TelemetryReport.FindingDiscovered(findings, executionDurationMs: 45);
    }
}
```

### Step 2: Creating Finding & Evidence Items

```csharp
var evidence = new FindingEvidenceItem(
    module: "Pharmacy",
    sourceTable: "simrs.farmasi_resep",
    recordKeys: "resep_no=RX-202611-0092",
    debitTotal: null,
    creditTotal: null,
    varianceDelta: null,
    trace: "Batch B-102 dispensed after expiration date."
);

var finding = new FindingItem(
    targetEntityReference: "RX-202611-0092",
    title: "Expired batch dispensed in active prescription",
    baseSeverity: "High",
    evidence: evidence
);
```

### Step 3: Registering the Probe in Dependency Injection

In `Program.cs`:

```csharp
builder.Services.AddDetectorProbe<PharmacyExpiryDetectorProbe>();
```

## 6. Embedded Webhook Listener Contract

Central PrIMA issues synchronous webhook calls to trigger instant inspections (`DetectorWebhookClient`):

- **Method:** `POST /webhooks/{detectorKey}`
- **Timeout Budget:** 15 seconds synchronous contract
- **Request Body:**
  ```json
  {
    "detectorId": "e1f13b19-216a-4933-9114-6e84dbfb8972",
    "triggerSource": "Manual",
    "issueId": null,
    "dispatchedAtUtc": "2026-11-22T08:00:00Z"
  }
  ```
- **Response Format (200 OK):**
  ```json
  {
    "outcome": "Passed",
    "durationMs": 42,
    "failureReason": null,
    "findings": []
  }
  ```

### Manual Testing with cURL
```bash
curl -X POST http://localhost:5090/webhooks/pharmacy-expiry-detector \
  -H "Content-Type: application/json" \
  -d '{"triggerSource": "Manual"}'
```

## 7. Windows Service Deployment

To deploy the runner as a continuous Windows Service on a hospital server:

```powershell
# 1. Publish the project to a target directory
dotnet publish src/backend/PrIMA.Detectors/PrIMA.Detectors.csproj -c Release -o C:\PrIMA\DetectorRunner

# 2. Register the Windows Service
sc.exe create "PrIMADetectorRunner" binPath= "C:\PrIMA\DetectorRunner\PrIMA.Detectors.exe" start= auto

# 3. Configure recovery on failure
sc.exe failure "PrIMADetectorRunner" reset= 86400 actions= restart/60000/restart/60000/none/0

# 4. Start the service
net start "PrIMADetectorRunner"
```

## 8. Windows Task Scheduler Deployment (Run-Once CLI)

To schedule recurring execution without running a permanent daemon process:

1. Open **Windows Task Scheduler** (`taskschd.msc`).
2. Create Task -> **"PrIMA Detector Hourly Pass"**.
3. **Trigger:** Daily, Repeat task every 1 hour for a duration of 1 day.
4. **Action:** Start a program
   - Program/script: `C:\PrIMA\DetectorRunner\PrIMA.Detectors.exe`
   - Add arguments: `--run-once`
   - Start in: `C:\PrIMA\DetectorRunner`
5. Ensure **"Run whether user is logged on or not"** is checked.
